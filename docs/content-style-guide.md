# 內容撰寫風格指南

本檔是**整理版摘要**，把散落在 `Meta_Dev_Knowledge.md` 各處、跟「怎麼
寫這個網站的文字內容」有關的規則收攏到一處，方便新增/改寫文案前快速
查閱。**權威版本仍是 `Meta_Dev_Knowledge.md` 裡對應的 PAT 條目**（本檔
每節都標了來源 PAT 編號）——本檔不是第二份源頭，只整理不改寫；PAT
條目本身若有異動，以那邊為準，本檔需要跟著同步更新。

## 30 秒版

- 對讀者一律用「你」，不用「使用者」當第二人稱代稱（可以當名詞標籤，
  如「使用者提交」徽章）
- 不用行銷腔／製造虛假急迫感的催促語，不濫用驚嘆號（但「立即」「馬上」
  「趕快」若是如實描述真實法規/安全時效，不算違規，見一節校正說明）
- 說明性文案「結論先行＋精簡列點」，同時講「這是什麼」＋「怎麼用」
- 連結文字要能預期導向什麼，不用「點此」「了解更多」
- 台灣繁體用語（使用者非用戶、應用程式非app、網路非網絡……）
- 德文專有名詞：同一頁/同一資料檔內第一次出現才附中文說明，之後用中文
- 不確定的事實寧可標「未確認」，不要編——但客觀可查證的公開事實（官方
  網址等）AI 可主動查證補齊，這不算違反零虛構原則

## 一、口吻與語氣（PAT-162，準則本體見 Meta_Dev_Knowledge.md 16-42 行）

**核心規則**：
1. **口吻統一**：一律第二人稱直接對話（「你」），不用「使用者」「用戶」
   等第三人稱指稱訪客本人；不用過度熱情或行銷腔（避免「立即」「馬上」
   「趕快」等製造虛假急迫感的催促語、驚嘆號濫用）；語氣沿用既有陪伴/
   教練調性（外事局指南、FAQ 已是此調性的既有範例）。
   > **2026-08-13 實測校正**：對現有內容跑過`scripts/check-content-style.mjs`
   > 後發現，「立即/馬上/趕快」不能無腦禁用——既有內容裡這幾個詞多半是
   > 描述真實法規/安全時效（「搬家立即 Anmeldung」「立即向外事局報失」
   > 這類真的有期限壓力、如實告知讀者的建議），跟行銷頁「立即註冊搶
   > 優惠！」那種製造虛假急迫感催促消費完全是兩回事。真正該擋的是後者
   > ；前者是誠實告知真實急迫性，不算違規。
2. **簡潔**：能一句講完不用兩句；避免「進行○○的動作」「針對○○做
   處理」等贅語結構，改用直接動詞（例：「進行搜尋」→「搜尋」）。
3. **結構**：說明性文案優先「結論先行＋要點」（見二節卡片格式）。
4. **同時講「是什麼」＋「怎麼用」**：功能說明類文案（空狀態、頁面標題
   副文、按鈕輔助文字）不可只寫「這是什麼」留使用方式讓讀者自己摸索。
5. **連結要可預期**：連結文字本身需可預期會導向什麼，不用「點此」
   「了解更多」等無資訊量措辭。

**判斷框架**（PAT-162 稽核時確立，用於快速判斷邊界案例）：
- 「使用者」一詞禁用的是**對讀者本人說話的散文**，不是**內容分類
  標籤／第三方作者署名**——「使用者提交」「使用者建議」徽章、「匿名
  使用者」等第三方顯示名稱佔位字串、「其他使用者」指涉讀者以外的第三
  人，這些是名詞片語標籤，允許保留。
- 邊界案例：「第 N 位註冊使用者」這類統計徽章標籤，判定為名詞片語性質
  而非對讀者的散文稱呼，維持不改。
- 導覽列／下拉選單／分頁籤等短詞彙標籤，不需套用「結論先行＋要點」
  「what+how」的完整散文結構要求。
- **不適用本準則**：外事局指南、隱私政策權利義務條款本文、GDPR 條款
  編號、德文專有名詞既有翻譯慣例（見三節）、資源分類卡片內文（見二節，
  PAT-152 已建立獨立格式標準，不套用本節語氣細則）。

**狀態提示的語氣分級**（PAT-165）：「非正常運作」狀態不是一律套用同一
種警示樣式——仍可正常使用、只是性質改變的狀態（如「已變更」「停更
可用」）用溫和提示；可靠度有疑慮的狀態（如「內容老舊」「需人工確認」）
才用較強烈的警示色。過度一致的警示語氣反而會讓讀者對真正需要注意的
項目降低敏感度。

## 二、結構格式（PAT-147 → PAT-152）

說明性文案（尤其資源分類卡片）採三層結構：**結論先行一句
（summary）＋精簡列點（points，5 秒可讀完）＋可收合細節（detail）**。
純粹重組既有內容為這個結構，**不新增原文沒有的事實**——這不是重新
查證的機會，只是排版重構。若原始內容僅含單一事實、無法再切分成獨立
列點，允許只寫 summary、省略 points，不強行拆成空洞列點湊數。

## 三、用詞與翻譯慣例（PAT-37 / 38 / 39 / 40）

**德文專有名詞首次原則**（PAT-37 擴展至全站 → PAT-39）：
- 每個 UI 頁／每個資料檔內，同一個德文專有名詞第一次出現時附中文
  說明（或於 `title_de` 呈現）
- 之後同頁/同檔的 procedure / common_mistakes / description / body
  一律用中文；功能性識別詞（Termin、SCHUFA 等常見於德國官方表單的詞）
  可視語境保留德文
- 保留德文的例外：`title_de` 欄位、官方機構名（Bürgeramt／
  Ausländerbehörde 等）、官方連結顯示名、documents 內正式表單名
- 專有名詞英文縮寫（APS、DSH、GDPR）全站首次出現附一次全稱，之後可
  直接用縮寫

**特定用詞統一**（PAT-38）：不用「封鎖帳戶」，一律「限制提領帳戶」；
Sperrkonto 視覺上首次以「限制提領帳戶（Sperrkonto）」形式出現，之後
只用中文。

**台灣繁體用語規範**（PAT-40）：全站 UI 文案、資料檔內容、錯誤訊息、
Toast 一律用台灣繁體字型與詞彙，常見對照：
應用程式（非 app，但 "app" 縮寫可用）、網路（非網絡）、伺服器（非
服務器）、電子郵件（非郵件）、帳戶（非賬戶）、履歷（非簡歷）、
品質（非質量）、介面（非界面）、使用者（非用戶）、造訪（非訪問）。
引用外部資料時翻譯為繁體。

> **2026-08-13 實測校正**：「網路 vs 網絡」不是單純非黑即白——「網絡」
> 指涉**抽象/社會網絡**義（人脈網絡、學術網絡、語意網絡）在台灣繁體
> 中文本來就是合法既有用法，跟簡體中文把「網際網路/電腦網路」也寫成
> 「網絡」是不同語意範疇。本站既有內容已有「德語詞彙語意網絡查詢
> 系統」「學術網絡與國際會議機會」等合法用例。這條規則真正該擋的是
> 「網際網路/電腦網路」義寫成「網絡」，不是全面禁用這兩個字。

## 四、事實正確性邊界（零虛構原則，PAT-183）

必填欄位（如 url）缺值時，AI 可對**客觀可查證的公開事實**（官方網址
等）主動查證補齊，不算違反零虛構原則；但**主觀/未公開事實**（費用
細節、政策內容等）查不到就是查不到，要標示「未確認」，不能推測填入
——這條界線延伸自婚紗行銷知識庫等其他專案共用的同一條鐵律：查證到
的公開事實可以填，AI 自己編的不行，兩者不能混為一談。

## 五、錯誤訊息（PAT-16，補充）

所有 Supabase 錯誤透過 `errorMessages.ts` 的 `translateError()`
統一過濾，避免 raw 錯誤直接展示給讀者；未命中的 code 保留原文，raw
訊息一律 `console.error` 供除錯（不對讀者顯示技術術語）。改錯誤文案
只需要改這一個檔案，不用到處找散落的錯誤字串。

## 六、既有規則沒涵蓋到的新情境

依 PAT-162 稽核經驗：新文案先比對本檔「30 秒版」快速判斷是否落入
規範範圍；真的遇到本檔未涵蓋的新情境（新的內容類型、新的語氣兩難），
記錄判斷理由並比照 PAT 格式寫回 `Meta_Dev_Knowledge.md`，本檔再回頭
補上摘要與來源編號，不要只改本檔不留原始決策記錄。

## 七、逐步教學型清單格式（PAT-188，2026-08-14 新增）

專指 Edu workflow（`src/data/edu/*.ts`）的 `procedure`／`common_mistakes`
這類一步一項的教學清單，跟一、三節講的一般散文/用詞規則並存、互不
取代：

- 每個 item 只裝一個獨立念頭，不用「，」「——」把兩件事硬塞進一行
- 單行硬性上限 30 字（含標點）——拆分後務必用 `node -e` 之類方式
  程式化計算 `.length` 逐行驗證，不用眼睛估算 CJK 字數
- 只留功能性語氣（動作指令、事實陳述、法源依據）。「不用擔心、放心、
  別怕、務必」只是範例詞，不是完整清單——真正標準是這句話是不是在
  陳述事實/下指令/引法源，還是在額外做修辭渲染、勸誘、下價值判斷
  （如「真正風險是⋯」「越早辦越好」，即使沒命中任何範例詞也算違規，
  無法靠關鍵字比對自動抓，需人工逐行重讀＋跟同檔案其餘平行欄位
  〔如 `meta.timing`〕比對語氣是否一致，見 PAT-188 2026-08-14 修正）
- 提到具體公司名/商業平台（如 Verivox、Check24）前，先查證是否
  真的「全國通用」；不是全國提供服務的品牌不該出現在「全國通用」
  框架的內容裡，優先引官方監管機構或法規本身當唯一來源
- 規則時效性宣稱（如「2025 年 6 月起⋯」）：查證當下若該規則已完整
  生效，改陳述現況本身，不沿用會顯得過時的過渡期措辭
